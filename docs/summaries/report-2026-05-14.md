# mamba-dvc — Project Code Infrastructure and Capabilities Summary

*Report date: 2026-05-14*

## 1. Executive Summary

**mamba-dvc** is a from-scratch, GPU-accelerated implementation of FFT-based **Digital Volume Correlation (DVC)** designed for synchrotron µCT imaging of rat bone instrumented with a metallic screw implant. The reference target is a `(960, 1280, 1280)` float32 volume (~6.3 GB) processed on a 4× NVIDIA A6000 workstation (196 GB aggregate VRAM, 128 GB host RAM) under Python 3.14 + CuPy v14 + CUDA 13.x.

Algorithmically, v1 implements a **single-pass FFT normalized cross-correlation (NCC) pipeline** with Gaussian sub-voxel peak refinement, mask-aware Points-of-Interest (POI) admission, and a Westerweel-Scarano normalized median outlier test. Two NCC kernels coexist: a fast cyclic kernel for A/B comparison and a **zero-padded linear NCC with Lewis (1995) overlap-aware denominator** which is the production default; the latter removes a previously-diagnosed shrinkage bias that scales with `|u|/W` in the cyclic kernel. Sub-voxel accuracy is empirically below the 0.1-voxel target on textured synthetic data without any iterative warp or pyramid stage.

The codebase currently comprises **~15,200 lines of production Python across 41 modules** and **~4,700 lines of tests across 41 test files**, organized around a deliberate `pure-core / wrapped-driver` separation. The pure single-pair function `pipeline.correlate.correlate()` is wrapped first by a single-process multi-GPU dispatcher (`gpu.dispatch.correlate_multi_gpu`), then by a persistent dispatcher (`MultiGPUDispatcher`) which amortizes spawn and CUDA-init cost across time-series workloads, and finally by the time-series driver `pipeline.series.correlate_series`. Beyond compute, the project ships a zarr-v3 I/O stack with named store profiles, manifests and verifier; a YAML-driven batch campaign runner with materialize-once / iterate-many semantics and resumability; a Typer-based CLI (`inspect`, `budget`, `run`); a phase-timing instrumentation layer; a validation suite covering both analytical synthetic fields and experimental ground-truth fields; and an optional PyVista-based visualization extra.

Quality is enforced by `ruff` (with `D` / `NPY` / `B` / `SIM` rule sets), strict-mode `pyright`, **`jaxtyping` shape annotations on every public array signature** with optional `beartype` runtime checking under test, and `pre-commit` mirroring CI. All public functions are documented under the NumPy docstring convention.

### 2.2 Type system, shape contracts, and quality gates

- **`jaxtyping`** annotates every public array signature in `core/`, `pipeline/`, `io/`, `gpu/`, and `validate/`. A shared shape vocabulary (`z`, `y`, `x`, `points`, `w`, `batch`, `pairs`) is declared once in `types.py` and reused everywhere.
- **`pyright`** runs in strict mode on `mamba_dvc/` (`pythonVersion = "3.14"`, `pythonPlatform = "Windows"`).
- **`beartype`** is wired into test wrappers for runtime shape enforcement without burdening production code.
- **`ruff`** enforces formatting, isort, pyupgrade, numpy-specific lints, and pydocstyle (NumPy convention) at `line-length = 95`; per-file ignores relax docstring rules in `tests/` and `validate/`.
- **`pre-commit`** mirrors the CI gate (`ruff format`, `ruff check --fix`, `pyright`).

Frozen dataclasses (`DisplacementField`, `DisplacementSeries`, `GridSpec`, `VoxelSpacing`) carry immutable invariants; for example, `DisplacementField.__post_init__` asserts the documented `valid == (status == POIStatus.OK)` invariant — a guard installed after a buffer-aliasing bug in the multi-GPU dispatcher (see `docs/triage/multi-gpu-aliasing-bug.md`).

## 3. Capabilities

### 3.1 Core algorithmic pipeline (single pair)

`pipeline.correlate.correlate()` is the pure single-device entry point. Its sequence (plan §2):

1. **Grid construction** (`core.grid.build_grid`) — emit POI centers on a regular lattice; `floor((dim − W)/stride)+1` per axis. At the canonical `W = 96`, `overlap = 0.5` on the target volume this yields ~11,875 POIs.
2. **Mask admission** (`core.grid.filter_by_mask`) — drop POIs whose subvolume has less than `mask_threshold` (default `0.9`) valid-voxel fraction. Status `MASKED`.
3. **Sub-volume extraction** (`core.extract.extract_subvolumes`) — batched gather of `(batch, W, W, W)` tiles for ref / def / both masks.
4. **Preprocessing** (`core.window.preprocess_subvolumes`) — masked-mean subtraction (statistics on unmasked voxels only), separable 3D Tukey window, post-window zeroing of masked voxels. Tukey defaults are per-mode: `α = 0.0` (rectangular) for linear NCC, `α = 0.25` for cyclic.
5. **Batched FFT NCC** (`core.ncc.correlate`) — two kernels:
   - `correlate_cyclic`: single `rfftn`, conjugate-multiply, `irfftn` at window size `W`; whole-window L2 normalization. Fast but has a documented shrinkage bias toward zero of order `|u|/W` (see `docs/insights/error-minimization.md`).
   - `correlate_linear`: zero-pads each volume to `2W` per axis, cross-correlates in the padded domain, crops the central valid-lag block, and re-packs to cyclic-FFT layout so downstream `peakfit` is mode-agnostic. Optional `normalization="overlap"` adds Lewis's per-lag overlap-aware denominator via two auxiliary FFT correlations of `ref²` and `def²` against an indicator box (six FFTs total). The Lewis path removes the cyclic bias and is the production default.
6. **Peak localization + sub-voxel fit** (`core.ncc.peak_displacement` + `core.peakfit.gaussian_subvoxel_fit`) — separable 3-point log-parabolic fit along each axis, exact under the Gaussian-peak assumption that an FFT-NCC of a band-limited textured volume satisfies to a very good approximation.
7. **Search-radius gate** — POIs whose integer-peak magnitude exceeds `search_radius` (default `W // 2`) are flagged `OUT_OF_RANGE`; displacement and confidence are zeroed.
8. **Outlier rejection** (`core.outlier.detect_outliers`) — Westerweel-Scarano normalized median test on a 3×3×3 lattice neighborhood, mask-aware (already-invalid neighbors are excluded so screw-adjacent POIs are not systematically flagged). Runs on the assembled host lattice after multi-GPU gather.

Output: an immutable `DisplacementField` carrying `(positions, displacements, valid, confidence, status, grid_shape, spacing, window)` with `.save_npz` / `.load_npz` persistence.

### 3.2 Multi-GPU dispatch

Two siblings live in `mamba_dvc.gpu.dispatch`, both built on a shared inner helper (`pipeline._internal.correlate_admitted_subset`) — the same algorithmic core, called either in-process or in worker processes:

- **`correlate_multi_gpu(...)`** — fire-and-forget multi-GPU dispatch. Architectural invariants:
  - One Python process per GPU via `multiprocessing.spawn` (Windows-safe).
  - **Volumes and mask are replicated** on every GPU; POIs are sharded block-wise along the lattice-Z axis to preserve spatial locality for the outlier test.
  - IPC uses `multiprocessing.shared_memory` (`gpu.shm.publish` / `attach`).
  - No inter-GPU communication during NCC. Per-shard sparse partials (full-length `MASKED`-defaulted arrays with the shard's slots filled) return through a unidirectional pipe; the parent scatters them into merged buffers with no merge logic.
  - The outlier test runs on the assembled lattice at the parent, so 3×3×3 neighborhoods see consistent data across shard boundaries.
  - The single-device path (`len(device_ids) == 1`) skips spawning entirely and serves as the multi-process regression baseline.

- **`MultiGPUDispatcher`** — context-managed persistent pool. Hoists per-series state (workers, mask, optional anchored reference, grid, shard indices, auto batch) into `__enter__` so each `.correlate(...)` call is compute-only. This amortizes the per-call spawn (~1.5 s) and CUDA context init (~3 s) over a whole time series instead of paying it per pair. Worker protocol over duplex pipes:
  - `("pair", deformed_handle, ref_handle | None)` → `("ok", disp, conf, stat)` or `("err", repr, tb)`
  - `("shutdown",)` → graceful exit

### 3.3 Auto batch-size oracle

`gpu.budget` answers the question "given free VRAM on each device and the resolved `(window, mode, normalization, has_mask)` tuple, what is the largest `batch_size` that fits?". Three composable layers:

- `kernel_footprint(window, mode, normalization)` — analytic per-POI transient bytes plus per-call fixed overhead. Coefficients (e.g. 36 B/POI for cyclic+global, 232 B/POI for linear+global, 480 B/POI for linear+overlap) are deliberately conservative pending a calibration script (`docs/plans/batchsize-oracle-v1.md` §4).
- `resident_bytes(inputs)` — bytes that workers pin on each device before any FFT work starts.
- `estimate_max_batch` / `recommend_batch_size` — combine the above with `probe_free_vram` (the single CuPy seam) and a `_HEADROOM_FRACTION = 0.15` margin.

`batch_size="auto"` is the default on both single-device `correlate()` and `correlate_multi_gpu()`; the multi-GPU path probes every device cold and logs a greppable resolution line on stderr (`auto.batch_size=… auto.free_bytes_min=… auto.per_poi_bytes=…`). The cost model is testable on CPU-only hosts because only `probe_free_vram` touches CuPy.

### 3.4 Time-series driver

`pipeline.series.correlate_series` lifts the single-pair function to an iterator of `(t, frame)` tuples. It is the same kind of pure function as `correlate()` — no filesystem, no state across calls — and packages results in a `DisplacementSeries`. Three pairing topologies are exposed through `PairingStrategy`:

- **`REFERENCE_ANCHORED`** — every pair is `(frame_0, frame_t)`; the recovered field is the absolute (Lagrangian) displacement at `t`. Per-frame errors are independent; search-radius pressure grows with `t`.
- **`SEQUENTIAL`** — every pair is `(frame_{t-1}, frame_t)`. Fields are incremental; absolute fields are recovered by `DisplacementSeries.cumulative()`, which folds increments via semi-Lagrangian composition (`core.field_ops.compose_displacement_fields`).
- **`UPDATED_REFERENCE`** — reserved enum slot; raises until the v2 warper lands.

Per-pair failures (CUDA OOM, propagated worker exceptions) emit a `RuntimeWarning` and record a `SeriesPairStatus.FAILED` row with a zero-filled field rather than aborting the series. `cumulative()` halts composition at the first failure boundary. The driver accepts an optional `MultiGPUDispatcher` so the persistent-pool path is opt-in; the host-only baseline remains available for CPU dev hosts and tests.

A complementary error-evaluation module, `validate.series_error.evaluate_synthetic`, generates closed-form temporal fields, dispatches them through a configurable sweep of `(strategy × lag)`, and returns flat `PerPairErrorTable` + `CumulativeDriftTable` tables — the rapid-iteration workbench that separates per-step measurement noise from random-walk drift.

### 3.5 I/O layer: zarr-v3 with profiles and verifier

`io/dataset.py` exposes `DvcDataset.open(path, manifest=..., strict=...)` which:

1. **Resolves a `StoreProfile`** — a named structural schema (group names, array names, default mask, expected dtype invariants, default flow `axis_order` / `vector_order` / `convention` / `units`). v1 ships `bone_screw_synchrotron_v1`; new collaborators register their own with `register_profile`.
2. **Discovers a `StoreManifest`** — sidecar YAML beside the zarr root, or `.zattrs` payload, or explicit argument. Manifests override profile defaults (e.g. flow convention) and may subset the deformations.
3. **Runs the verifier** (`io.verify.verify`) — checks dtypes, shapes, axis order, and the presence of well-known arrays. `strict=True` raises `StoreVerificationError` on any error; `strict=False` returns the dataset anyway with a `VerificationReport` and a `broken_entries` map listing per-entry problems that did not block opening (e.g. a synthetic entry missing its `volume1`).

Opening reads no voxels; `dataset.load_pair(name, mask=...)` is the explicit materialization step and returns an `EvaluationPair` ready to feed into `correlate()` and into `validate.known_fields.evaluate_pair(...)`. The `GroundTruthField` wrapper carries axis/vector/convention metadata so push-forward vs pull-back ambiguity surfaces at load time rather than as silent ~50× error inflation.

### 3.6 Batch campaign runner (`mamba_dvc.run`)

`mamba_dvc.run.batch.run_batch(spec, ...)` turns a YAML `BatchSpec` into a directory of persisted results plus an aggregation `manifest.jsonl`. The runner:

- **Expands sweeps and explicit variants** (`run.config.BatchSpec.expand_variants`) into a flat list of `Variant`s, each with a stable identity hash and parameters pre-split into **three loop tiers** — *load* (`mask`, `dry_shape`, `flow_convention`), *grid* (`window`, `overlap`), and *compute* (`mask_threshold`, `batch_size`, `ncc_mode`, `ncc_normalization`, `search_radius`, `tukey_alpha`). Reordering the product so the most expensive tier rotates least is the central optimization.
- **Materializes once, iterates many** — opens the dataset once per `(store × deformation × load-slice)`, runs `load_pair` once, and loops the compute-tier variants inside.
- **Prefetches the next load group** in a single background thread (`_prefetched_load_groups`), gated by `psutil`-checked host-RAM headroom. Measured overlap efficiency against the NumPy-heavy consumer is ~1.9× (near-perfect for a two-deep pipeline).
- **Resumes** — re-running skips variants whose `.npz` + sidecar JSON already exist.
- **Persists** each result as a `DisplacementField` `.npz` plus a JSON sidecar carrying full provenance (config hash, git revision, Python/CuPy versions, timing breakdown).
- **Streams progress** through a `BatchObserver` protocol; the library is print-free, and the CLI plugs in a Rich renderer.

### 3.7 Command-line interface

Typer-based, registered via `[project.scripts] mamba-dvc = "mamba_dvc.cli:app"`. Three subcommands today:

- **`mamba-dvc inspect <path.zarr>`** — opens a store with `strict=False`, renders a Rich tree of every parsed slot (reference, masks with `[default]` tag, real `iterations/` entries, synthetic entries tagged with axis order / convention), shows the verifier panel in green / red, and supports `--verbose` (chunks / codecs / on-disk size), `--json` (machine-readable inventory), `--manifest`, and `--profile`. Exit codes are scripting-friendly (`0` clean, `1` verifier errors, `2` could-not-open).
- **`mamba-dvc budget`** — preview of the auto batch-size oracle for a given config without launching workloads.
- **`mamba-dvc run <campaign.yaml>`** — execute a `BatchSpec`. Flags include `--dry-run` (plan preview only), `--devices`, `--prefetch`, `--only KEY=VALUE`, and `--timing` (attach a `PhaseAccumulator` and print one consolidated breakdown at the end).

### 3.8 Validation

Two-tier strategy (plan §9):

**Tier 1 — analytical synthetic fields** (`validate/synthetic.py`, 818 lines)

Closed-form callables `u(coords) -> displacement` (and the temporal variant `u(coords, t)` for series studies):

- `rigid_shift`, `uniform_dilation`, `simple_shear`, `sinusoidal`, `linear_motion`, `compose`.

Band-limited noise textures (`make_texture`) and `warp(...)` (pull-back default, push-forward also supported with explicit sign-convention warnings) build `(reference, deformed, gt_field)` triples. Round-trip assertions through `correlate()` pin the < 0.1-voxel accuracy target on integer + fractional shifts, dilations, shear, and sinusoidal fields.

The **bias regression test** `TestLinearVsCyclicBias` is the cheapest construction that would have caught the cyclic shrinkage on day one and must pass for any PR touching `core/ncc.py`.

`validate/phantoms.py` provides a bone-like multi-region phantom (cortical shell, trabecular core, implant cylinder, optional defect cavity, multiplicative band-limited texture, mild final Gaussian) for visualization showcases and end-to-end smoke tests.

**Tier 2 — experimental ground truth** (`validate/known_fields.py`, 524 lines)

`run_and_evaluate` and `sweep` orchestrate the *materialize → correlate → score* loop end-to-end:

- `evaluate_pair(field, evaluation_pair, ...)` returns an `ErrorReport` with per-POI error vectors `estimated − ground_truth`, MAE / RMSE / p95 overall, the same stratified by `BoundaryDistanceIndex` (an amortized KD-tree-based distance-to-mask-boundary lookup that reproduces `scipy.ndimage.distance_transform_edt(~mask)` sampled at rounded POI voxels while touching only the foreground shell), and a confidence-vs-error correlation as a quality-signal sanity check.
- `BoundaryStratifiedTable` bins MAE / RMSE by distance from the screw, which is the expected location of higher error.

### 3.9 Phase-timing instrumentation

`mamba_dvc.instrument` provides opt-in structured timing under the `mamba_dvc.timing` logger at `DEBUG`. Three consumption modes:

1. **Silent** (default).
2. **Per-phase log handler** (verbose; meant for single-pair inspection).
3. **`PhaseAccumulator`** (a `logging.Handler` that aggregates `(count, total, min, max)` per phase across many invocations and renders one summary table). The CLI's `--timing` flag uses this via the `accumulating` context manager.

CuPy-side timings synchronise the current stream before reading the clock (`sync=True`) so numbers reflect kernel execution, not just launch — but only when the logger is enabled, so production cost is one `isEnabledFor` check per phase. Records carry structured `LogRecord` attributes (`mdvc_phase`, `mdvc_seconds`, plus phase-specific fields like `n_admitted`, `batch_size`, `n_devices`) so downstream consumers parse structured data rather than message text.

### 3.10 Visualization (optional)

Activated via the `viz` extra (`pyvista`, `matplotlib`, `ipywidgets`, `trame*`):

- `viz.volume.render_volume` / `render_isosurface` — composable PyVista renderers that mutate a caller-supplied `Plotter` and never call `.show()`, so the same code works for interactive notebook use and headless screenshot export.
- `viz._conversion.unify_spacing` — centralizes `VoxelSpacing` unit math; mixed `"voxel"` + physical-unit composition is a hard error rather than a silent conversion.
- Notebooks under `notebooks/` (showcase, debug, inspection, time-series showcase) drive interactive use; nbstripout via pre-commit keeps outputs out of the diff.

## 4. Architectural Invariants Worth Highlighting

1. **Pure-core / wrapped-driver separation** — `pipeline.correlate.correlate()` is a pure function and `pipeline.series.correlate_series` is its time-series counterpart; multi-GPU dispatch (single-shot and persistent), batch-campaign orchestration, and prefetch wrap the pure core without touching its body. This is what lets the v2 features in plan §10 (IC-GN, Padfield masked FFT, iterative warp, multi-level pyramid, dense-field densification) replace individual core verbs without refactor.
2. **Sparse-output convention** — `correlate_admitted_subset` returns full-length arrays of length `prod(grid.grid_shape)` where slots outside `admitted_idx` carry `POIStatus.MASKED`. Multi-GPU scatter is then a no-merge `out[shard_idx] = part[shard_idx]` over disjoint shards.
3. **Array-module-agnostic core** — every hot-path module duck-types over NumPy / CuPy via `cupy.get_array_module`, so the same code runs in single-device GPU, multi-GPU worker, and host-only CPU contexts. CuPy is imported under `try / except ImportError` everywhere; `gpu.budget.is_cupy_available()` is the single gate.
4. **Cold-probe discipline** — the auto batch-size probe runs *before* any volume publish and *before* any worker spawn, so it sees free VRAM as the workers will see it.
5. **No half-finished extension points** — `deformed_mask` already appears in the v1 signature so Padfield's masked FFT (v2) needs no API change; `DisplacementField.grid_shape + spacing + positions` are redundant by design so densification becomes a `reshape + B-spline` one-liner.
